# Testing and demo

Use Node 22.12+ (verified with Node 24.2.0) and pnpm 10.28.1.

- `pnpm install --frozen-lockfile`: install pinned tools.
- `pnpm dev`: open http://127.0.0.1:5173 for the demo.
- `pnpm typecheck`: strict TypeScript checks for source, demo, and tests.
- `pnpm build`: ESM, declarations, and explicitly exported CSS in `dist/`.
- `pnpm test`: pure Vitest tests.
- `pnpm exec playwright install`: install Chromium, Firefox, and WebKit if absent.
- `pnpm test:browser`: run all three Playwright engines, start Vite automatically,
  capture current screenshots under `docs/evidence/milestone-a/correctness/`, retain failure traces in
  ignored `test-results/`.

Stage 1 verified all commands above except browser installation (matching browser
binaries were already available). The sandbox blocks local server binding; browser
runs require execution with local server/browser permissions. Dependency download
also required network permissions. These are environment restrictions, not test failures.

Actual stable browser and screen-reader release checks remain scheduled for stage 9;
Playwright WebKit is not actual Safari verification.

## Stage-3 review and diagnostics

- `pnpm dev`, then `/`: live reference, independent geometry mount, and live
  side-by-side comparison. Buttons select One, expand/collapse, undo, and reset.
- `/?workload`: mixed-depth deterministic map with exactly 1,000 total and 500
  visible nodes (250 collapsed leaves each hide two children).
- `pnpm perf`: Chromium early workload diagnostic, writes JSON samples and a
  screenshot under `docs/evidence/milestone-a/correctness/`.
- `pnpm test:browser tests/browser/render.spec.ts --project=firefox`: targeted
  Firefox rendering verification; other projects can be selected identically.

Full browser tests also run the diagnostic in all three engines. Viewports are
1400×1000 for normal tests/workload and 1440×1200 for reference captures so the
entire 1226px-wide comparison is visible. Device scale is 1; widget zoom is 100%.
The comparison-only mount translates its root to (204,159) to align with the
supplied 605×324 Windows 100% DPI image displayed at native size; normal mounts retain centered roots.

Captures are review candidates, not approved screenshot regression baselines.
No screenshot pixel tolerance or self-generated screenshot assertion is used.
Never overwrite the four supplied reference images. The current candidate files
are regenerated by browser tests; retain explained before/after evidence when
changing their appearance, and record actual user acceptance before baselining.

Detailed results, known differences, and required later checks are in
[the current correction report](evidence/milestone-a/correctness/report.md). `checks.txt` and
`browser-checks.txt` retain the final gate output. Workload JSON records browser,
OS, hardware, sample values, and measurement limitations. The reported first
cache-clearing refresh happens after font readiness; it is not a cold navigation
or font-load benchmark. Final input-to-paint, frame traces, packaged-consumer,
actual stable browser, and manual screen-reader checks remain milestone D gates.

The initial 2026-09-05 evidence remains in `docs/evidence/milestone-a/` as a
historical comparison; the first correction remains in `100dpi/`. Browser tests
retain the earlier spacing candidates in `spacing/` and write current candidates
to `correctness/`; previous candidates remain in `checkbox-gap/` and `clearance/`. The 2026-09-07 user feedback authorized changes, not approval of
the resulting images. No approved pixel baselines exist yet. The six-line root
assertion expects 90px of text height (6 × 15px), matching the revised theme;
containment and non-overlap assertions remain unchanged.

The spacing regression checks label-to-line clearance, checkbox alignment beside
root/single-line/multiline text, and unchanged row/connector geometry. To reproduce
native screenshot ink-gap measurements, run
`python3 docs/evidence/milestone-a/clearance/inspect-spacing.py` (requires Pillow).
The current diagnostic includes all nonwhite descender pixels (channel threshold 255),
checks at least two blank rows beneath them in each engine, and verifies the gap
above N1 still matches the reference. Dark-ink measurements are retained alongside
these counts. The preceding spacing report excluded faint edges and overstated
visible descender clearance.

## Correctness review regressions

- `pnpm test:browser tests/browser/api.spec.ts`: malformed JavaScript commands,
  preserved undo/redo and event atomicity, FIFO reentrancy, callback errors,
  destruction during draining, and a 3,000-operation chain.
- `pnpm test:browser tests/browser/layout-edge.spec.ts`: trailing-newline and
  newline-only rows, root/checkbox geometry, mounting and refreshing under scaled,
  nested/nonuniform, and rotated hosts, then restoring normal scale.
- Edge-case JSON and screenshots are in `docs/evidence/milestone-a/correctness/`.
  Transform tests require exact equality of local boxes, paths, ellipse dimensions,
  and browser-rounded screen bounds before/after refresh. They do not use screenshot
  tolerances or assume infinite precision in screen-coordinate arithmetic.
